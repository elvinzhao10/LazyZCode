# LazyZCode Build Conventions (SHARED — every build agent MUST read this first)

LazyZCode is the **ZCode member of the LazySeries family**, produced as a
rename-port of **LazyQoder** (previous base v1.3.0; v1.3.1 surgical fix round;
lineage: LazyZCodex → LazyTrae → LazyBuddy
→ LazyQoder → LazyZCode). Output lives ONLY under
`/Users/Admin/Desktop/lazyseries/lazyzcode/`. The source repos
(`lazyqoder/`, `LazyTrae/`, `LazyBuddy/`, `lazykimi/`) under
`/Users/Admin/Desktop/lazyseries/` are READ-ONLY — never modify them.
Research material for this port lives in `.study/` (never shipped).

## Product name history

Public name: **LazyZCode** (repo `elvinzhao10/LazyZCode`). The internal
 Codename "LazyCode" is retired; any reappearance is a naming regression.

## Rename map actually applied (LazyQoder → LazyZCode for ZCode)

- `lazyqoder` → `lazyzcode` (identifiers, filenames, state dir `.lazyqoder/` → `.lazyzcode/`)
- `LazyQoder` → `LazyZCode`, `LAZYQODER` → `LAZYZCODE` (product/machine names)
- `QODER_PLUGIN_ROOT` → `CLAUDE_PLUGIN_ROOT` (ZCode expands `${CLAUDE_PLUGIN_ROOT}`
  in plugin hooks and plugin `.mcp.json`; `${ZCODE_PLUGIN_ROOT}` is an alias)
- `QODER_PROJECT_DIR` → `CLAUDE_PROJECT_DIR`, `QODER_PLUGIN_DATA` → `CLAUDE_PLUGIN_DATA`
- `qodercli` / `QoderCLI` → `zcode` (host CLI binary), `Qoder` → `ZCode` (host display name)
- `lazyqoder-plugin/` path references → `plugins/lazyzcode` (the ZCode plugin is
  nested one level deeper: the market root is `<repo>/plugins/`)
- `codebuddy`/`CODEBUDDY` residues → `zcode`/`ZCode`/`CLAUDE_*` (family rename residue)
- The Qoder CLI-only manifest `.qodercli-plugin/` and host mirror `.qoder/` are
  retired: ZCode uses ONE manifest at `plugins/lazyzcode/.zcode-plugin/plugin.json`
  plus the plugin-root `.mcp.json` (auto-discovered by the host).
- Skill/command names keep the `lazy-` prefix (`/lazy-ulw-plan`, 19 skills,
  20 commands); agents are `lazyzcode-<role>`; scripts are `lazyzcode-*`.

## What is intentionally NOT byte-identical (per-host, by design)

- `contracts/marketplace-route-contract.v1.json` — ZCode routes:
  `zcode-marketplace` (default) and `manual-skills-mcp-fallback` (recovery-only,
  excludes commands/agents/hooks). Payload inventory is regenerated with
  `node plugins/lazyzcode/scripts/lazyzcode-regenerate-marketplace-contract.js`
  after ANY edit under skills/, commands/, agents/, hooks/, mcp/, or `.mcp.json`
  (run from the repo root; it also refreshes the `.sha256` sidecar).
- `contracts/zcode-hook-consumers.v1.json` — ZCode's 7 hook events
  (SessionStart, UserPromptSubmit, PreToolUse, PermissionRequest, PostToolUse,
  PostToolUseFailure, Stop). ZCode has NO PreCompact/SubagentStop/etc.; the
  executor-evidence gate from SubagentStop moved into the review skills.
- `contracts/lazy-harness-lifecycle.v1.schema.json` — host enum carries `zcode`
  (single host), product enum carries `LazyZCode`; digests are pinned in
  `scripts/lifecycle/bootstrap.js` and mirrored in the `.sha256` sidecars.
- Hook scripts emit ZCode-safe stdout: either valid JSON
  (`{"additionalContext": "..."}`) or NOTHING; deny = exit 2 with stderr reason.
  Diagnostics go to stderr, never stdout.

protect them by cross-repo comparison against the sibling v1.3.1 roots, not
by sidecar digest. Docs boundaries live in
`docs/reference/model-routing.md`. Cross-repo parity is asserted by
`tests/v016-automatic-tooling-contract-parity.sh --lazyzcode-root <repo>
--lazytrae-root <LazyTrae repo>`.

## ZCode-host facts every agent must respect

- Install/update/removal happen through Settings → Plugins. Add the public
  GitHub URL with root `marketplace.json`, or use local `<repo>/plugins` as a
  fallback; there is NO `zcode plugin marketplace add` CLI, no
  daemon/serve/prewarm, no rules injection. Dev-only validation:
  `zcode plugins validate plugins/lazyzcode` (when the CLI is on PATH).
- Project memory is `AGENTS.md` (workspace) + `~/.zcode/AGENTS.md` (user);
  the family's `workbuddy.md` pointer convention maps to AGENTS.md.
- ZCode tools for agents: Read, Bash, Write, Edit, Agent, TaskOutput,
  TodoWrite, TodoRead, WebFetch, WebSearch, Skill. There are no
  Grep/Glob/TaskCreate/TaskUpdate tools; agents restrict tools via the
  frontmatter `tools` allowlist.
- The MCP profile gate (`mcp/profile-gate.sh`) defaults unset/empty
  `LAZYZCODE_MCP_MODE` to `orchestrated` so all six declared servers stay
  active out of the box; genuinely deferred servers exit 0 quietly.

## QUALITY BAR

- Preserve source structure, section order, and markdown quality.
- Every ported file must be self-consistent after renaming; no dangling
  references to retired machinery (service adapters, IDE surfaces, mirrors).
- MIT license text VERBATIM; NOTICE credits LazyZCodex (MIT) and OmO (SUL) as

## Verification discipline

- Package: `bash plugins/lazyzcode/scripts/lazyzcode-load-check.sh` →
  `PACKAGE_READINESS=full`.
- Aggregate: `LAZYZCODE_VERIFY_SUITE=all bash plugins/lazyzcode/scripts/lazyzcode-verify.sh`
  (core | lifecycle | all; doctor, smoke, docs, security, mcp-test,
  hook-pipeline, load-check, contract-check, shell regressions, node tests,
  pytest).
- Naming: `node scripts/check-product-naming.js`.
- Python: 3.10+ syntax is used throughout; scripts resolve `python3.13`–
  `python3.10` when the system `python3` is older (or set `LAZYZCODE_PYTHON`).
- Release gates: `bash plugins/lazyzcode/tests/publication-regression.sh`,
  `node scripts/check-product-naming.js`, tag `vX.Y.Z` only after green CI.
